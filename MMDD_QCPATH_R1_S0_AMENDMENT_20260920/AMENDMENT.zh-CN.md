## 1. S0 分成两项就绪条件，不让 B 阻断独立的 A

### 1.1 S0-A：启动 A seed13 的唯一前置

必须完成：

1. 原始数据、有效 train_fit 划分、指定 BASE、冻结 object embeddings、目标向量/索引、第一跳与 production 函数的解析和锁定。
2. 按第2节从原始 GT 生成 A 的有效训练人口和 P/I/N，检查空集、非法引用与监督边界。
3. 仓库生产实现的 A-T01–A-T13；不能用附件 reference 的37项测试替代。
4. production 的真实小样本调用：零残差与 BASE 一致，训练/exact/ANN 使用同一条件向量公式，Evidence/retention/Equal 没有被重定义。
5. 独立临时 adapter 上至少一次真实逻辑 batch 的 loss→backward→optimizer step→评测集成，包含文本、图像、尾 batch/多正例等可用真实情形；数学边界可由合成例补足。临时模型随后丢弃，正式模型重新初始化并恢复规定 RNG。

S0-A 通过后，直接执行 prepare-a、A-EONLY seed13、A-QE seed13、evaluate-a、decide-a。不再询问“是否继续”。不能为了启动 A 而先要求三对象 Teacher forward 或 B-T12 通过。

### 1.2 S0-B：只在 A13 达到原门槛后完成

S0-B 包括 B 全部必要输入/特征覆盖、B-T01–B-T14、真实三对象集成、B资源适配。S0-B 通过才允许启动两个 B seed13 作业。

允许在 A 之前或 A 执行期间进行不增加训练的 B 源码实现、文件检索和缺项清单准备；不要求提前实现全部 B，也不允许提前启动 B 训练。第4节的新增 Qwen 前向仅在 A13 PASS 后允许，以免 A 失败时浪费编码成本。

状态分开记录：`A readiness`、`B prerequisite readiness`、`stage gate status`。只用原有 PASS/FAIL/BLOCKED/NOT_REACHED/NOT_APPLICABLE 枚举。B缺特征时可记录 `B prerequisite=BLOCKED` 与 `B training=NOT_REACHED`；不能把它写成 B 方法效果失败、永久取消B或S0-A失败。

若 A13 FAIL，遵守原停止条件，不补算、不训练B、不跑seed29。若A13 PASS但B尚缺必要输入，只保留独立的B阻断；不改成QT-only主方法，也不绕过B直接跑A29。

## 2. 训练监督人口：恢复原协议 train_fit，不吸收校准桶

### 2.1 本次决定

本轮所有新增参数训练仅允许使用历史协议的 `train_fit` 监督。`cal_fit`、`cal_check`、dev、test 的相关性/witness标签均不得用于新参数更新、正例闭包、ignore mask、支持标签或训练样本选择。

这是对 v1.0 只写“原始 train”而遗漏历史校准子桶的明确修订，不把执行者此前采用完整 dataset train 的解析追认成正确，也不把它说成已有训练污染——按当前报告没有正式训练。

### 2.2 划分信息不是历史训练列表

允许读取独立的、只含 query/source-group 到协议桶映射的既有 split manifest。它是数据划分元数据，不是 [positive, negative…] 训练组合。不得从旧训练list的成员反推出本轮训练人口。

若独立划分manifest不存在，可使用原始source-group信息与历史已锁定的划分算法/seed精确重建；禁止重新随机划分，禁止默认取前90%，禁止为凑14592而删样本。无法恢复原划分时，停止监督构造并记录缺失项。

从原始标注读取记录时，先按已锁定query归属限定train_fit，再建立 G/D/W/Epos/P/I/N。禁止先用全部train建立Epos或ignore集合、再仅过滤训练item；这会继续使用校准监督。独立无条件ET标签仅在其本身明确归属于允许的监督范围时使用；归属不可证明的标签不能擅自纳入。

保留原合法目标/证据语料与静态索引；**限定监督来源不等于删除cal/dev/test对应的无标签对象内容**。

### 2.3 A 和 B 同时生效

A：使用train_fit内全部有效(q,e)，重新计算N_pair、Q_tr、每query的m_q与权重，重新生成固定顺序。每epoch更新数仍为ceil(N_pair/128)。没有达到原始活跃条件的item按原规则处理，不强凑历史数量。

B：每类最多2048个query的抽样母集也只来自train_fit；保持原抽样seed/namespace、每类上限与所有其他规则。不得用完整dataset train选B子集。

根据用户转述，完整train为16156 pair/6315 query，历史train_fit为14592/5707。这些是待本地回执验证的数值，不是强制断言。输出两种人口的集合差、归属桶计数与最终有效人口；差异应可由明确划分/标签规则解释，不能将原因写成笼统“重建数量不同”。

若最终N_pair=14592，则每epoch114次更新、3epoch共342次；若并非此数，按公式记录真实预算，不截断/复制补数。

## 3. 硬件：本次明确允许2×RTX4090，算法合同不变

本修订将“本次必须A100”改为“本次使用已报告的2×RTX4090 24GB，执行端先核实实际型号/显存”。这是仅针对本轮的硬件修订，不修改用户今后实验的默认硬件偏好。

A可以两个独立进程各占一张卡，也可以串行。禁止用DDP把两个实验臂合成一个训练；权重、optimizer、RNG、score cache、输出目录相互隔离，原冻结缓存只读共享。

A保持 logical batch128、microbatch32、FP32、autocast关闭、TF32关闭、严格确定性策略、同初值、同样本顺序、同损失与优化器。不能因为显存不足自行改AMP/BF16、减少目标分母、修改logical batch、减少更新或更换模型。

B保持FP32与logical batch8、query microbatch1；仅按原文从path microbatch 8/4/2/1中在S0-B确定，并保留原来允许的等价激活checkpoint规则。仍无法满足则只阻断B，不能裁路径/候选。

单个目标矩阵约94MB不等于模型总显存。分别实测A逻辑batch和B三对象训练的峰值allocated/reserved memory。该必要资源测试不是新实验分支。

所有本轮公平时延比较在同一GPU型号/同软件环境/同缓存条件下重测。不得把4090成绩标成A100，也不得用跨设备逐位差异直接判为算法错误或声称两设备训练必然完全相同。若原规定确定性算子不可运行，禁止自动降为warn_only。

## 4. B特征缺失：允许有限的同配方离线补齐，禁止降级

### 4.1 修订H01的准确含义

Qwen仍完全冻结；禁止骨干微调、训练过程中Qwen前向、全湖重新编码、换embedding方案、换量化版本、换prompt、改分辨率或截断以节省资源。

唯一例外：A13 PASS后，可对本轮B确实需要而现有兼容缓存没有的evidence对象，使用历史T0原特征生成配方进行一次性离线补齐。该动作属于输入资产准备，不是新增Teacher/Student正式训练作业；其成本必须单独记录。

此例外是对旧H01的明确覆盖；不得声称旧H01原本允许新增前向。

### 4.2 先建立完整必需集合，再计算缺口

必需对象取并集：

- 原规范B训练子集、自然候选/retained路径、两个epoch规定的增强witness；
- 原规范B所有正式评测环境，包括BASE固定环境及A-QE生成的对应环境；
- 原规范12.2生成的E-swap donor；
- 上述调用涉及的query、target和evidence。

候选与donor映射按原规则生成，不能根据缓存是否存在而选择对象。缺口通过“必需集合减去已验证兼容缓存”得到。

BASE dev retained路径中的132个缺失evidence只是已报告的局部缺口，不得当作全B缺口上界。5个内容别名是否已从132扣除应在清单里明确；不在聊天里猜127。

先查现存兼容cache与精确内容别名。别名必须同时匹配真实输入内容、模态、序列化/processor配置和特征生成身份；仅同URL、标题或语义相似不合格。所有规范evidence ID、path slot与multiplicity均保留，alias只能改变底层特征存储引用。

### 4.3 固定范围上限，避免“补齐”扩大为新预计算工程

本轮累计最多新增编码 **2048个不同的缺失evidence对象**；另允许至多16个已有对象作兼容性复算（每种模态最多8个，按规范ID顺序选择，不看GT/分数）。这是本次修订明确设定的资源上限，不是服务器已测缺口。

两个seed与全部B环境合计共用此上限；同对象不重复编码。新增磁盘仍受原100GiB目录上限及200GiB空余要求约束。不补齐整个225720-evidence库，不复制整套旧hidden-state缓存。

缺口超过2048、必要原图/正文无法解析、原特征配方不可恢复、或原资源上限不足时：输出具体数量/字节/缺项并阻断B；禁止只选前2048个然后删掉其他query或路径。A及已完成回执保留。

### 4.4 内容和数值兼容要求

必须恢复并锁定原Qwen权重与revision、tokenizer/processor、prompt、实际序列化文本或图像输入、token/image处理参数、backbone计算dtype及特征提取层/切片规则。不能以“同是Qwen3-VL-Embedding-8B”为充分依据。

冻结backbone的补算dtype必须沿用历史特征配方；它与A/B新训练一律FP32是两个不同层级，不得混淆。禁止为了在4090上加载而自行换量化或新特征表示。

在已有对象上先复算，再用原T0的冻结压缩器得到C_x/g_x，与从旧缓存获得的同层输出比较。必须满足shape、mask、token组语义完全相同；每个有效向量均有限。非零向量比较：相对L2误差≤0.01且余弦≥0.999；相对L2分母为max(旧向量L2,1e-12)。零向量必须两边都为零，否则不兼容。阈值是本修订预定的兼容性工作点，不是逐位一致保证，不得看结果后放宽。

任一对象未通过、或输入/提取身份不一致，均阻断本次新增特征混用；不能用“dev Recall看起来没变”替代兼容性检查。原文B-T01等其他容差完全不变。

补算保存为独立sidecar，不覆盖旧特征或A使用的原z/目标向量/索引。遵守原9.3/9.4，只持久化本轮允许的冻结压缩表示C_x/g_x及必要的来源记录；完整hidden states用后释放。不得缓存可训练Transformer、role或scoring输出。

评测证据的编码与压缩只能使用其原始内容，不能读取dev witness/相关性标签挑选或改变特征；按已锁定自然路径/donor确定编码对象，不构成标注注入。

### 4.5 B开训前的通过条件

对本次B两个arm、全部既定训练视图、所有评测环境和donor的必需集合，兼容特征覆盖必须为100%。两臂共用同一版本的缓存解析器与feature sidecar。必须先完成B-T01–B-T14及S0-B，然后才启动B。

若A29后按原协议新增的评测环境引入缺失对象，允许在累计2048上限内用完全相同规则补齐；不得更换已训练B模型、重新挑超参或重跑seed13成绩。每个评测环境的feature依赖另存manifest。
