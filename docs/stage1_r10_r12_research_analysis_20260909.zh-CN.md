# Stage 1 R10–R12 Research Audit

## 技术结论：候选分布有改进，属性补全与 join 的证据链仍未打通

**目前最有依据的进展，是 R12 在 P/R 保持可训练时，通过部署检索难例改善了完整正确路径的可达性。**同为 356 个 edge 更新，C-candidates 为 255/678，C-base 为 222/678，增加 4.87 个百分点，source-group 配对 bootstrap 95% 区间为 [3.21, 6.67]。两个额外 Student 种子方向一致。这是可保留的 Stage 1 中间结果。

**尚未得到证据支持的，是显式 path 训练、多模态互补，以及 evidence 补属性后带来的最终 join 增益。**Path 阶段选回 step 0；融合存在明显 implicit/explicit 取舍；端到端补值全部为空。不能把这些事实改写成完整方法已经成功，也不能把当前实现的全空输出视为多模态科研假设已被否定。

下一步建议分成两个小闭环：先让“已确认 evidence → 正确值 → 正确 join”的诊断可测，再针对 E→T 与 path 信用分配修正训练。继续扩大训练轮数、增加 evidence 权重或追求更高总 Recall，都无法替代这两个闭环。

## 比较范围：三轮是诊断演进，不能直接拼成精度上升曲线

分析快照为 2026 年 9 月 9 日的已有实验文件。阅读了科研方案、三轮计划、FINAL、独立 REVIEW、原始指标与部分逐样本预测，并核对相关训练/验证实现。只做离线复算，没有启动训练、模型调用、数据扩建或修改历史实验。

EntiTables v9 是同湖 transductive 设置，未标注湖对象可见，训练监督应仅来自 train-fit。R10 原 test 后来参与问题分析，R11/R12 中只能称历史回归集；当前没有独立确认集。R10 权重祖先、负例监督及选择器有审计发现，因此以审计后的边界解释历史结果，不能只沿用 FINAL 的“协议通过”。

| 口径 | 分母与解释 | 不能替代的结果 |
| --- | --- | --- |
| R@10 | 每 query 正 target 召回率，再宏平均；dev 1,198 queries | evidence 质量、补值准确率 |
| ValidPool | dev 678 个 implicit 正(Q,T)中，至少一条正确完整路径进入池 | target 已进入最终 top10 |
| ValidB / RowB | 在正确目标自身 B=4 保留后，正确路径存在率 / 支持行数除以5；未入池计零 | 实际路由、生成和 join |

R10 test 路径分母是 646，R11/R12 dev 是 678；Task F 是另外冻结的 128 个 dev query（96 implicit、32 explicit），31 个实际入队可恢复正对、80 条有真值的行。不能把这些分母连成一条总体漏斗。所有百分比差值均使用“百分点”。现有 recovery 标签提供确认支持下界，不穷尽真实可用 evidence。

还有一个重要区分：**direct 找到了 target，但只有 evidence 补出缺失连接属性后才能 join，同样支持论文 idea。**D100 外发现是一项更强、但更稀有的结果；不能把它当成 evidence 补属性机制唯一的成功定义。应分别报告“已有候选被补全后可连接”和“候选也由 evidence 新发现”。

## R10–R11 排除了部分解释，也暴露了第二跳损伤

R10 不是“只差融合调好”。固定 test 上，Raw 正确路径到池 213/646，p_frozen 为 159/646，E01 为 14/646；保留 top4 后分别为 188、124、11，F2 最终只有 71、45、1。E01 在融合前就已严重失去正确路径。p_frozen 只是冻结 P 的定位消融，不能用它替代论文的可训练主线。

p_frozen 的 F4 相比自身 direct，ValidPath 从 6.81% 增至 7.89%，总 R@10 却从 25.77% 降至 16.31%；救回 19 个正目标、挤出 131 个。局部机制代理增益真实存在，但代价也必须同时保留。

R10 的 F2 使用 evidence 权重 0.05，在 direct100、RRF 常数60的设定中，pure-evidence 最高票为 0.05/61，低于 direct 第100名的 1/160。因此它的 top10/20/50 无法准入 D100 外目标；该对照适合观察已有候选重排，无法检验“evidence 新发现 target”的主张。F1/F2 等编号在不同轮次含义有变化，报告必须带规则名称。

R11 修正误负例后，B0/B1 的 edge 端点仍都只有 8/678，path 端点都为 9/678。修复必要，但不足以解释和解决坍缩。长程 KD-off 也坍缩，不能把原因全部归给蒸馏。

历史独立审计还发现 R10 的已知正例被扩池误标、少量 test-only corruption 监督混入、选择器未完整执行破同分；R11 也存在弱负标签、PCA 参照与空 evidence 通道等问题。R12 的修正和复评提升了可审计性，但不能追溯净化旧权重或恢复盲测身份。

**Path 训练另有第一跳损伤。**健康 C1 step356 接续 path-only 后，ValidPool 为255→244→186，第一跳正确对529→519→412；path+0.1 edge 末端也为186。两个 path step0 的 P/R 张量与 C1 step356 一致，最终选中 step0 意味着收益属于 C1，不属于 path 学习。

Teacher 也不是普遍更强：base 候选上 token Teacher 的宏 R@1 32.45%，PCA 为64.94%；hard 候选上 Teacher 为12.38%、PCA为8.96%，优势依关系不同。Q→image 为28.52%对6.45%，Q→text却为8.03%对14.77%。因此需要关系和候选难度分层的 Teacher 检验，不能预先把失败定义成 Student 压缩能力不足。

对四个R11历史 checkpoint、同一固定64-list batch及历史局部列表KD的一阶梯度诊断中，ranking/KD 夹角余弦均为正，约0.435–0.909；参数 anchor 梯度远小于排序梯度。它不能替代当前R12全候选KD或path梯度诊断，也不足以排除所有局部冲突，但不支持“普遍梯度相反”已被证实。小参数漂移/MSE正则存在同样不能证明功能几何受到保护。R12 C-function的函数/主目标梯度比已达15.05%，ValidPool仍221对比222，不能简单解释为正则太弱。

ANN/exact也没有把长程损伤解释为单纯索引误差：C-candidates的text→table exact正邻居命中在356/659/1318步为31→26→1，固定分母89。这是具体关系上的损伤证据。Teacher首批screen与extension分别记录3,085,525和6,052,897个unique scored pairs；后者是冻结Teacher补分，非Teacher重训。即使Student更新数相同，也不能宣称完整计算成本相同。

这是跨轮复算里一个容易被总指标遮住的差异。全部 query 都是5行，implicit 构造最少要求2行恢复；最终 verifier 的60%门槛对应3行。按照每个正(Q,T)中不同 query_row_id 的恢复记录去重：

| R10协议 train-fit | 6,347 | 5,345 | 1,002 | 15.79% |
| R10协议 train-calibration | 688 | 573 | 115 | 16.72% |
| dev | 678 | 330 | 348 | 51.33% |

这个变化有构造上的解释：manifest 允许 train 每条join链/桥接属性变体最多5个不相交query view，而dev/test仅1个；参考构造实现中，多 view 先为每个 view 预留最少2条恢复行，dev/test 单 view 优先使用可恢复行。该机制与观测一致，但未独立证明当前参考源码与历史构建版本逐位相同。不能直接将分布差异叫数据损坏或标签遗漏。

**训练的“有任意正确路径”目标与最终“至少三行可连接”目标没有天然对齐。**84.21%的 train-fit implicit 正对在现有记录中只有2行支持。但这是标签证据的限制，不能把它当真实可恢复性的绝对上界，也不能为了故事简单把最终门槛改成40%。应保留40%/60%两种用途，分析不同支持层，并在训练侧做等预算的2行/3行以上分层采样对照。

方案还有一个真实预算约束：B=4、每条 evidence 唯一路由、query5行时，单 target 最多4行获得 evidence。此时100%补全不可能，60%需要至少3条有效且分配到不同正确行的 evidence。top4里“有一条正确证据”离最终门槛仍很远。

## 保留与融合：覆盖收益存在，但属性判别和 explicit 代价没有解决

R12 Student 固定池上，D1 soft coverage 比 D0 增加5个 ValidB，RowB从10.50%到11.09%；D2 稀疏 argmax 降为205/678、9.82%。Raw 的D2−D1实际 RoutedSupport为−0.53pp，区间[−1.11,+0.03]。因此没有数据支持把 D2 直接替换成优化方案。

R11 的 soft coverage 收益更小：只净增4个确认支持行（320→324/3390），区间跨零；至少3行的正对27→24，正确保留图像 evidence 次数25→13。它可能以损失深覆盖和图像为代价提高两行覆盖。行相似度启发式不是属性支持概率；一条 evidence 被选到不同 row，也不意味着它包含该 row 所需属性。

Task B 的256条独立 primary 与52条 second review均未完成。当前候选按 recovery/high-score/冲突等层富集，模型辅助比例不能当全湖precision。另一个预算问题是：256条中训练侧只有128，支持模型需至少64确认正和64确认负；首批只有恰好64/64且没有unknown才可能通过数量门槛，还须满足source-group要求。应预计追加训练侧独立审核，而不是将unknown负标或挪用dev标签。

## 端到端：先解决全空补值与验证定义，才能解释 oracle 负结果

对原始 JSONL 独立复算，并把相同队列的两套系统只计一次：128 queries共1280个候选位置，39个qrels正目标入队。最终接受1017个join，全部来自direct分支；26个命中qrels，991个不在已知正目标中，按现有评测口径precision为2.56%。Evidence分支执行420次验证，没有一次通过。

这里的“991个false”是当前qrels评估定义，还没有逐例独立人工确认。因为论文区分逻辑join与一般相似/偶然值重合，必须审计系统接受的列对是否真的满足任务语义、以及qrels是否遗漏其他合法join。该结果足以说明当前“verifier通过”不能作为最终正确性的依据，却不能代替人工认定991对全部不合法。

| F-a 固定目标与oracle列条件 | 实际评估正对 | 真值行 | 生成器最终选中的E有确认支持的行 | 非空输出 | 正确恢复 |
| --- | ---: | ---: | ---: | ---: | ---: |
| no-evidence，同生成器 | 30 | 78 | 0 | 0 | 0 |
| retrieved evidence | 30 | 78 | 33 | 0 | 0 |
| oracle evidence | 30 | 78 | 69 | 0 | 0 |
| 标为wrong-attribute的替换 | 1 | 2 | 0 | 0 | 0 |

**69/78条oracle真值行已选到历史标签确认支持的 evidence，但没有产生非空值。**这把最紧急的诊断定位在后续定位、生成、输出解析与输入约束，而不是单纯扩大召回。69条是资产级确认支持，不等于FOCUS裁剪后仍保留答案；后者也必须独立检查。

F-a共455条行输出全空；完整链2100条行输出也全空，其中908条有已定位 evidence。生成代码将“没有JSON起始符”“JSON解析失败”和真实空值都折叠成空字符串，且未保存原始completion/解析状态。chat template没有显式关闭thinking。这些都是排查方向；没有原始输出就不能认定thinking或解析一定是根因。

另一个新复算结果是：retrieved 条件路由阶段确认支持35行，生成器最终选中的证据只支持33行。至少2行在“分给该行的材料中有正确支持”之后又被定位/选优丢失。应区分“路由集合含正确证据”与“实际送入生成器的那条证据正确”，不能把前者当后者。

Direct verifier遍历列对，按cell语义相似阈值判断覆盖，再取最好列对。991个qrels未命中接受项里，747个已经是100%覆盖；若只把60%门槛提升为100%，现有接受项中仍有747个未命中和22个命中，precision也仅约2.86%。这只是冻结输出上的描述性筛选，不能替代新的校准实验；但已说明“只提高覆盖阈值”不足以区分语义相似与合法join。

还存在四个会影响归因的实现/测量缺口：

1. Task F把`evidence_score`设为`-final_rank`，替代了方案要求的独立evidence分数e_T。F1的rank来自direct排序，evidence先验因此受direct影响。修复后才能检验独立分支贡献。
2. “40个可恢复对在top10 union”的统计使用所有query目标ID并集，没有逐query限定。实际完整链分母为31对、F-a为30对；不能把差额10解释成“检索不到evidence”。完整链0/80的行分母不因此失效。
3. wrong-attribute只有1对，且代码从其他target的正evidence中挑“不属于本target已知正集合”的材料。非membership不等于已确认错误属性，不足以形成独立属性反事实；Task B审核仍缺失。
4. frozen fusion恰好就是F1，两套队列和预测完全相同。delta=0、CI=[0,0]是结构性恒等，不能当一次有效的融合因果检验。F-a也筛掉没有retrieved evidence的正对，只是条件读取诊断，不能外推到128个query的总体机制成功率。

同生成器的no-evidence条件确实进行了生成调用，这是必要控制；但当前提示词严格禁止使用外部知识。因此它测的是该任务约束下的无证据行为，不能把全空解释成模型没有记忆。判断evidence依赖还需要有效的错误属性替换、来源定位以及成功值人工核查。

| P0：全空首先受读取/生成链阻塞 | 从现有失败诊断中另标工程开发样本；固定oracle目标/列/正确E，保存原始completion、token数、解析类别、裁剪后文本/区域；再拆oracle span/ROI与真实FOCUS | 先证明已确认可读材料能输出可评分值；若oracle span仍失败，停止扩大检索/全链。工程修复样本不能冒充最终盲测 |

| P1：path目标给错误/单行捷径分配了信用 | 固定C1健康起点、目标和路径池，对比当前target-only与一个训练侧已确认row/attribute-support辅助目标；记录direct/evidence/各边梯度与路径责任 | 正target分数上升必须伴随正确属性路径占比、多行实际支持提高；错属性干预应消除相应收益。无独立标签时不训练属性负例 |
| P2：训练缺少三行补全监督机会 | 只用train-fit，对2行/至少3行支持及模态分层采样做等样本预算对照；不改变dev/test构成与最终60%标准 | 同时报告自然分布与各支持层，不能仅在富集3行以上子集报告效果；未标注行不负标 |

P1的path辅助目标是对原target-level训练的显式扩展，不是已经证明的改进。它的动机是当前标量路径和/LSE允许由高分但属性不匹配的路径解释正target，而target正例本身并不保证路径正确；该解释仍需通过路径责任和反事实实验检验。优先用训练侧支持标签改善离线信用分配，不把在线非可分解reranker静默换成主方法。

首轮不要同时改候选、Teacher结构、学习率、正例loss和融合。先复用C-candidates的短程结果作为可训练基线；关系目标稳定后再比较token/pooled Teacher和完整Teacher–Student种子链。功能正则若要重测，应由固定训练batch上的梯度比例确定一次设置，而不是连续按dev分数扫系数。

## 论文叙事：当前可写什么，还缺什么

可以写：“在EntiTables-v9同湖开发设置中，部署检索难例改善了可索引Student的完整证据路径召回；实验同时揭示了构造列表指标与自然两跳检索的差异，以及候选准入、行覆盖和显式召回之间的取舍。”必须附上条件Student复现、开发选择和历史协议的边界。

当前不能写：“细粒度Teacher已学到优于相似度的通用joinability”“path蒸馏已成功”“多模态互补已经确立”“证据已补出缺失属性并提高最终join”。这些是下一步要检验的主张。

最终核心实验至少需要两个配对量：①固定候选/目标/列，无evidence失败而正确evidence带来有依据的新值和正确join；②在相同在线预算下，证据检索新发现的目标最终也完成这一过程。第一项成立、第二项很小，仍可支持较窄的“属性补全使既有候选可连接”贡献；只有候选Recall提升、没有正确补值，两项都不能成立。

三项会改变下一轮决策的问题应先回答：oracle资产裁剪后是否仍包含答案？被verifier接受但未在qrels中的列对究竟是漏标合法join还是语义误判？图像在独立审阅下有多少确实可读出所需属性的样本？答案出来前，保留原始负结果，并把资源优先投入能够区分这些解释的实验。
