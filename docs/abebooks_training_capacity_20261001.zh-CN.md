# AbeBooks 优化方向更正与规模核查

13 个查询、test 1 个的副本无法承担所需训练和评测。先过滤到只剩少量案例，再继续导出训练文件，是错误的交付顺序；格式与连接校验通过不能弥补这个问题。

本轮重新只读核查了完整输入。未修改原数据、没有启动新训练或模型推理。

## 已核实的资源

- 1,158 条图书记录和 131 条卖家记录，5,441 个现有素材；有图片的源行共 1,157 条。
- 原始抓取的 1,158 条成功记录包含 12,556 个不同销售卡片 ID。这些不是 12,556 本独立图书，也不是现成的 query 标签，不能直接用作样本数。
- 当前导出的 5,441 条抽取记录中，作者候选涉及 1,064 条源行；抽取记录里存在图片输出价格、评分等可疑内容，不能直接转为真值。
- 更完整的历史审核缓存有 21,544 条审核记录。作者字段有 1,680 条，原判定 supported 的记录覆盖当前素材对应的 127 条源行。其中完整值按保守姓名规范化一致的有 89 行。
- 将最终审核抽取值与源值重新做保守姓名规范化比较，包括此前判定 contradicted 的记录，共有 224 行相符，涉及 104 个源组、281 个素材。典型误拒是 `Ousterhout, John K.` 与 `John K. Ousterhout`。这 224 行是应复核的候选，不是新确认真值，不能自动覆盖历史拒绝标签。

## 固定 174 表的结构容量

只选目标中作者键唯一、源值有效的行；implicit 要求目标不含 title，并剔除书名直接出现完整作者名的行。每个源组优先选现有 implicit 目标，组内按不重复用行估算：

| 每个 query 行数 | implicit 候选上限 | explicit 候选上限 | 合计 |
|---|---:|---:|---:|
| 2 | 212 | 186 | 398 |
| 3 | 139 | 121 | 260 |
| 5 | 65 | 60 | 125 |

对应 451 个 implicit 结构候选行、393 个 explicit 结构候选行，共 94 个源组。逐组明细在 [STRUCTURAL_CAPACITY.json](../work/abebooks_training_capacity_20261001/STRUCTURAL_CAPACITY.json)。

**这些是证据审核前的结构上限，不是已可用于训练的规模。** 还需要执行新增证据审核、增补价值检查、全湖正例补全和实体/证据跨 split 检查。最终可用数量只能更少。两行 query 是需要明确固定的 query-by-example 设定，不能与五行任务混报；跨 query 不重复用行不等于源组完全独立。

因此，仅重筛旧的 21 个作者查询不能解决任务。下一步应首先明确 AbeBooks 是独立训练集还是联合训练中的评测集，再定训练/验证/测试规模要求；从全量证据补标，修复姓名顺序造成的误拒，并重建 query。需要改划分时另存新版本，不能把历史暴露数据称作全新测试集。若现有原始数据经充分审核后仍达不到要求，应扩充原始图书/关系数据，而不是用重复行组合或大量显式查询掩盖隐式监督不足。
