# AbeBooks 其他连接属性检查

日期：2026-10-01。检查对象：`dataset/abebooks_standalone_all5_balanced_20261001`。本次只做分析，没有更改数据集、标签、划分或 viewer 加载版本，也没有调用新的抽取模型。

**出版社 `publisher` 是最值得进一步审核的单列候选；出版年 `publication_year` 有部分结构空间，但当前没有可直接复用的合格五行隐式任务。** 书名适合直接书目匹配，但当前候选投影已移除书名；价格、评分等即使数值较独特，也不适合用来制造多模态连接任务。

## 范围和判定条件

检查当前副本保留的 117 张图书源表、1,158 条图书记录，以及 13 张卖家源表、131 条卖家记录，逐列对照全部 174 张候选表的当前字段投影。当前训练查询和恢复标签仍只有 authors；其他属性的历史恢复记录来自保留的原始版本。

结构筛查要求：源行按待测属性值与本源候选表执行等值连接，只返回该源记录，并且能获得非空的新字段。每个候选五行视图的五行均需满足这一 oracle 条件；隐式视图只需至少两行有历史恢复证据。后者不要求五行都能恢复。

统计中的“结构容量”是每个源表选择一个目标视图后可形成的五行视图数上界。它不包括新的全湖标签判定、跨行提示审核、证据重新核验或训练划分。不同属性使用的源行重叠，容量不能相加，也不能当作已经增加的独立查询数量。

## 出版社为何需要严格筛选

仅清理标点和显式 `(edition …)` 后缀时，出版社约有 123–124 个不同规范化值；原始字符串含有 `Morgan Kaufmann`、`Morgan Kaufmann Publishers`、`Morgan Kaufmann Pub` 等同一品牌的不同写法，不能把这些写法当成不同出版社来提高区分度。

补查历史模型读取值与源值一致性后，标点／版次清理口径得到 **8 个“五行且至少两行有历史证据”的结构候选**。进一步做常见出版社品牌别名的敏感性分析后，只剩 **3 个结构候选**。这张试验性别名表还没有通过权威映射审核；两个数都不是已批准的新查询数。

三个统计口径不能混用：`COLUMN_AUDIT.json` 的初筛容量为 10，使用历史批准记录判断支持；`PUBLISHER_NORMALIZATION.json` 进一步检查历史 `model_value` 与源值相符，得到 8，再合并常见品牌别名后得到 3。这一步核对的是历史模型输出值，仍不等于重新读取图片或逐条核验最终复核意见。

别名合并会同时改善证据值匹配、增加同值碰撞。例如 Addison-Wesley 的多种品牌写法合并后出现于 388 条源记录；在某个目标表中，必须排除把一本书连到该出版社其他书目的情况。出版社可用于严格筛选后的子集，不能把所有出版社重叠都写成正例。

本次还查看了四张相关封面，记录于 `PUBLISHER_VISUAL_SPOTCHECK.json`。一个具体反例是 `st_book_086` 的第 851 行《Risk Management for Computer Security》：图片只能读出 Elsevier 标志，源字段和历史标签却具体到 `Butterworth-Heinemann`。母公司标志不足以单独证明该子品牌。其他样本显示 MK 或 Routledge 品牌标志，仍需明确标志识别和品牌规范化规则。这是知晓源值的 Codex 抽查，不是新的盲读或人工金标，没有据此写入恢复标签。

## 出版年及复合键

年份有部分局部可用性：按当前目标投影，421 个源行至少在一个本源目标中可以用年份唯一返回自身，单独审视年份的五行结构容量为 52。但是这些是源真值的 oracle 检查，不能代替恢复标注。仅有的两条历史年份恢复都在 `st_book_107`，均存在目标内年份碰撞；其中《Visual C# 2005: How to Program》的源出版年 2005 还直接出现在可见书名中。

`publisher + publication_year` 比单独出版社更有区分度。在相同的品牌别名敏感性口径下，80 张目标表同时具有两列，本源目标中可无歧义连接的源行由单独出版社的 384 行增加到 607 行；五行结构容量由 32 增至 92。当前 132 个查询视图中，53 个能通过本源目标的复合键 oracle 检查。

但历史证据中，同时具有 publisher 和 publication_year 批准恢复记录的源行是 **0**。因此它是需要另行设计的复合键方向，不是可以立即替换当前单列标签的现成任务。也可以研究把年份作为可见约束、只恢复出版社，但那会改变查询输入与连接判定，需单独说明和验证。

## 不能把抽取缓存当作监督数量

`attribute_extractions` 保留了 5,441 条历史读取记录，里面的候选字段远多于最终批准恢复记录。它们包含源属性上下文，且有内容不支持输出值的情况。

对文本提案做宽松字符串筛查后：价格候选覆盖 260 个源行，但只有 2 行能在相应文本找到所报值的字符串；评分候选覆盖 139 个源行，只有 1 行能找到值字符串。出版年候选覆盖 274 行，仅 50 行出现所报年份，而且出现的年份还可能是作者任职年份或另一部书的出版年份。字符串出现也不能证明实体对应关系。

例如某份作者简介产生了出版年、价格等整套字段，实际文字只介绍作者、研究经历以及另一部作品。这些提案不能直接扩充成新金标。出版社和年份的新增监督应重新做不给源答案的证据读取，并区分本书、其他作品及作者经历。

## 建议

首先复核出版社候选，明确品牌／子品牌规范化和错误书目扩张规则；通过后才考虑在新副本中加入。出版年作为下一层候选，需要补充真实证据并逐目标检查歧义。若希望更大幅度改善连接区分度，应把复合键作为独立实验方向，不能靠价格、评分或细碎格式差异凑连接属性数量。

详细统计位于 `work/abebooks_join_column_audit_20261001/`：`COLUMN_AUDIT.json`、`PUBLISHER_NORMALIZATION.json`、`COMPOSITE_KEY_AUDIT.json`、`TEXT_EXTRACTION_AUDIT.json` 和 `PUBLISHER_VISUAL_SPOTCHECK.json`。当前数据、标签及 viewer 均未变动。

续接会话后，已从实际源表和目标表独立重算出版社两种归一化口径、复合键容量及各列目标表覆盖数，结果与上述记录一致。另核实全部 132 个查询均为五行，implicit 至少两行具有恢复记录，train/dev/test 分别为 40/40、13/13、13/13（implicit/explicit）。原版与当前版的 18 个 manifest／数据分片在本次复核前后内容哈希一致。复核结果见 [RESUME_VERIFICATION.json](../work/abebooks_join_column_audit_20261001/RESUME_VERIFICATION.json)。这些检查验证统计与文件一致性，不构成新增证据资格认定或模型效果验证。
